- Why the same PCB layout is failing alignment or compatibility validation.

- Whether registration and component comparison use consistent coordinate systems.
- Whether image resizing, cropping, or aspect ratios affect the alignment result.

Do not guess the cause. Use actual code paths and reproducible tests.

## PHASE 2 — Make reference-point detection automatic

Automatic alignment must be the DEFAULT.

When a golden PCB is uploaded:

1. Detect the PCB outline.
2. Automatically propose four spatially distributed, stable reference points.
3. Prefer mounting holes, reliable board corners, or other fixed board features.
4. Draw the four points visibly on the reference image.
5. Verify point ordering and geometric validity.
6. Save the points in the golden-board configuration.

When an inspection image is uploaded:

1. Automatically locate the corresponding PCB.
2. Estimate the 2D board transformation.
3. Align it with the golden reference.
4. Display the aligned result and registration confidence.
5. Continue automatically to component inspection when registration is reliable.

The industrial camera viewpoint is fixed overhead. The board can translate and rotate in the image plane.

Reuse the existing YOLO landmark detector where it provides reliable predictions, but implement an independent classical-CV fallback.

Evaluate suitable methods such as:
- Mounting-hole detection
- Board contour matching
- Feature matching with RANSAC
- ECC-based image registration
- Masked phase correlation where appropriate

Do not use unstable component positions as board-registration anchors.

Manual landmarks must remain available as a FALLBACK, not the default.

If the operator manually corrects the reference points, persist that reference configuration and automatically register subsequent inspection images against it.

Do not require manual point selection for every inspection.

## PHASE 3 — Fix false board-mismatch decisions

Separate BOARD REGISTRATION from COMPONENT DEFECT DETECTION.

A missing or rotated component must not automatically invalidate an otherwise matching PCB layout.

Evaluate board compatibility using stable board geometry and distributed structural evidence.

A board should be classified as BOARD_MISMATCH only when there is convincing evidence of a different layout.

Use independent conditions for:
- Successful registration
- Different PCB layout
- Uncertain alignment
- Component abnormalities

Do not simply lower all thresholds or bypass safety checks to force successful results.

Record the reasons for each decision.

## PHASE 4 — Make automatic component inspection work

After successful registration:

1. Load the verified golden component map.
2. Automatically propose component regions when no verified map exists.
3. Compare each expected component location with the registered inspection image.
4. Detect missing components using multiple structural signals.
5. Detect local component displacement and rotation.
6. Report component IDs, evidence, and defect types.
7. Produce annotated inspection images.

Distinguish:
- GOOD
- MISSING_COMPONENT
- MISALIGNED_COMPONENT
- BOARD_MISMATCH
- NEEDS_REVIEW

A rotated component must not be mistaken for whole-board rotation.

The specific `misaligned_002.png` example must be evaluated using the actual inspection algorithm.

Do not hardcode its expected result or component coordinates.

Ground-truth annotations can be used to score predictions, but never as the algorithm's prediction source.
