# 7. DEVELOP OUR OWN REFERENCE-GUIDED DEFECT VERIFICATION ENGINE

This is one of IndustryAI's primary engineering contributions.

Do not use ParsaVictor's separate assembly-defect model for missing or shifted component classification.

Implement our own verification pipeline using ParsaVictor component localization, OpenCV, mathematical geometry and reference-image comparison.

## A. Component correspondence

Run component detection on both:
- Golden reference PCB
- Inspection PCB

After board registration, transform detected inspection component coordinates into golden-reference coordinates.

Match components using:
- Spatial proximity
- Component class compatibility
- Bounding-box dimensions
- Intersection over Union
- Visual appearance evidence

Use one-to-one assignment, for example the Hungarian algorithm, where appropriate.

Prevent multiple reference components from matching one inspection component.

Do not match solely using component count.

For closely spaced, identical components, use local reference positions and geometric consistency.

## B. Detect missing components

For every reference component:

1. Locate the expected region on the aligned inspection image.
2. Search for a corresponding component detection.
3. Validate potential matches.
4. If no match exists, compare the expected region against the inspection image.
5. Evaluate local structural, edge and appearance differences.
6. Determine whether the component is likely absent or whether the detector may have missed it.

Return MISSING only when evidence supports absence.

If evidence is inconclusive, return NEEDS_REVIEW.

Never automatically classify every unmatched detection as MISSING.

## C. Detect shifted components

For matched components, calculate center displacement:

d = sqrt((xi - xr)^2 + (yi - yr)^2)

Here:
- (xr, yr) is the reference component center.
- (xi, yi) is the aligned inspection component center.

Normalize displacement by component dimensions and account for residual board registration error.

Compare displacement against calibrated tolerances.

Distinguish local component displacement from an overall camera-position difference.

## D. Detect rotated components

Where reliable orientation information is available, estimate component orientation.

Use:

theta = atan2(y2 - y1, x2 - x1)

Calculate the smallest meaningful angular difference between reference and inspection orientation, accounting for component symmetry.

Use OpenCV contour, mask or oriented-rectangle geometry when justified.

Axis-aligned bounding boxes alone are not sufficient to reliably determine component rotation.

If orientation cannot be estimated confidently, return an uncertain result rather than inventing a rotation defect.

## E. IoU comparison

Compute:

IoU = Intersection Area / Union Area

Use IoU as a spatial matching feature.

High IoU with acceptable appearance and displacement supports PRESENT.

Low IoU combined with a valid nearby component match may indicate SHIFTED.

Low IoU without reliable correspondence does NOT automatically indicate MISSING.

## F. Visual verification

Implement local image comparison using appropriate OpenCV techniques.

Possible evidence includes:
- Structural similarity
- Edge-map differences
- Local texture differences
- Component occupancy
- Local appearance features

Account for reasonable illumination differences, reflections, image blur and registration uncertainty.

Do not rely on one global image-difference threshold.

## G. Decision system

Support:

- PRESENT
- MISSING
- SHIFTED
- ROTATED
- NEEDS_REVIEW

Also preserve inspection-level alignment and board-identity failure states.

Each defect should include:
- Component ID
- Expected location
- Observed location, if matched
- Defect category
- Supporting measurements
- Confidence or calibrated decision score where available
- Human-readable explanation

Thresholds must be justified using available validation images or explicit configuration.

Do not invent numerical accuracy claims.
