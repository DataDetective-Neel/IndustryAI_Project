## 2. Implement automatic golden-PCB component detection

This is mandatory.

When a user uploads a golden PCB image:

1. Automatically detect the PCB boundary.
2. Identify candidate component regions.
3. Generate component bounding boxes.
4. Display proposed boxes immediately on the reference image.
5. Assign stable component identifiers.
6. Allow manual correction, renaming, addition, and deletion.
7. Save the approved golden-board configuration.

Implement a practical OpenCV pipeline using appropriate combinations of:

- Image normalization
- Adaptive thresholding
- Edge detection
- Morphological operations
- Contour analysis
- Connected components
- Geometric filtering
- Candidate merging and suppression

Reuse existing models if useful.

Do not hardcode component coordinates.

Do not require the user to draw every component manually.

Do not classify arbitrary contours as verified components.

Where component identity is uncertain, mark it UNKNOWN and permit manual identification.

Use the golden PCB image and its verified component annotations from the dataset-generation work for testing, without hardcoding that board into the algorithm.

## 3. Implement reliable PCB inspection

The workflow must be:

Golden PCB upload
→ automatic component proposals
→ operator verification
→ saved golden-board configuration
→ inspection image
→ board registration
→ component comparison
→ defect classification
→ inspection result.

Account for whole-board 2D translation and rotation.

Compare components in registered board coordinates.

Detect:

- Missing components
- Component misalignment
- Board mismatch
- Registration failure
- Uncertain results

Use component shape, edge structure, texture, and geometric evidence.

Do not classify every color difference as a missing component.

Report per-component evidence and configurable confidence thresholds.

Preserve the original YOLO landmark detector if useful, but do not make manual landmark selection mandatory for every inspection.
