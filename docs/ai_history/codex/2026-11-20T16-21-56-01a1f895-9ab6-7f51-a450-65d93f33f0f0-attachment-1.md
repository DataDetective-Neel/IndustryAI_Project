## 1. Project goal and scope

A printed circuit board (PCB) can leave an assembly station with components missing. Build a local inspection tool that compares a new photograph with a known-good photograph of the same PCB layout. The operator marks which components to inspect. The app reports which marked components appear to be missing and highlights their expected locations.

The assignment describes a fixed factory camera. The live demo uses uploaded still photos and runs on a Windows laptop without internet access. The assignment leaves the PCB type open. Each inspection photo must show the same PCB layout as the active reference.

Example. The operator labels two rectangles on a complete reference board “C12” and “J1 connector.” If C12 is absent from a later photo of that layout, the app highlights the C12 location and leaves J1 unflagged. If both parts are confidently present and the photo is suitable for inspection, it shows green “OK.”

## 2. Operator workflow

1. Upload one sharp, known-good reference photo showing the full board.
2. Confirm the four board landmarks detected by the app. Draw and name a rectangle around each component to inspect. Allow zooming and box editing before saving the reference setup.
3. Upload one to three inspection photos in a batch. Process each independently so a failed photo still leaves the other results available.
4. Review the aligned overlay and the names and locations of missing components. Allow side-by-side viewing of the reference and inspection crops for a selected part.
5. Show green “OK” only when alignment is reliable and every marked component is confidently present. Flag ambiguous components for review while preserving confirmed missing findings on the same photo. Request a retake or re-upload when alignment fails or the photo is too blurred for reliable inspection.

## 3. Proposed architecture and inspection pipeline

Use React and Vite for the interface, FastAPI for the local backend, Python and YOLO26n Pose for landmark detection, and OpenCV for alignment and crop comparison. Record Streamlit as a possible frontend alternative.

### A. Train the landmark model before the demo

Fine-tune YOLO26n Pose on PCB photos labeled with a board bounding box and four ordered keypoints. Use four repeatable, distinguishable landmarks spread across the board plane, such as four identifiable corners where appropriate. Choose landmarks that remain visible when an inspected component is missing. Package the trained PCB-specific weights with the demo.

### B. Save the reference setup

Validate the reference photo and detect its four landmarks. Store the reference image, ordered landmark coordinates, and named component rectangles together. Keep coordinates in the reference image’s original pixel coordinate system so browser zoom and resizing preserve their positions.

### C. Align each inspection photo

Validate the photo and detect the same four landmark identities. Use OpenCV getPerspectiveTransform and warpPerspective to map the inspection image into the reference coordinate system. Check landmark confidence, point geometry, and coverage of the marked regions. Check agreement against independent stable board features where available. Generate an overlay of the two aligned photos for visual verification.

### D. Extract and optionally sharpen component crops

Extract the same rectangle from the reference and aligned inspection images for each marked component. Convert both crops to grayscale.

Make image sharpening a separate, configurable preprocessing step after alignment and before comparison. When enabled, apply the same mild unsharp mask to both crops. When disabled, pass the grayscale crops directly to comparison. Use the image quality checks to request a retake for blur severe enough to make inspection unreliable.

### E. Compare crops and assemble results

Use normalized correlation on edges or gradients as the initial comparison method. Use thresholds to classify each part as present, missing, or uncertain. Assemble a per-photo result with component names, locations, and inspection status. Keep the overlay and comparison crops available as evidence for the operator.

Record a Siamese network as an optional future crop-comparison experiment if enough labeled crop pairs are available.

### F. Validate the pipeline

Tune alignment checks and comparison thresholds on labeled development photos. Evaluate on a board layout held out from model training and threshold tuning. On the same labeled photos, compare sharpening enabled and disabled. Use missed parts and false alarms to choose the proposed default setting, and report reviews and retakes separately. Mark unmeasured thresholds, dataset sizes, latency, and accuracy as TBD.

### G. Prepare the Windows laptop

With Python installed, run setup.bat once while online. The script creates a project-local .venv and installs packages from requirements.txt. For the demo, FastAPI serves the prebuilt Vite frontend on localhost and loads the trained YOLO26 weights from disk. Include a restart-and-inspect test with Wi-Fi off.
